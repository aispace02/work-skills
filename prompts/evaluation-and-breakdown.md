# 上游提示词评估与本地改编说明

## 目的

本目录保存的是我根据个人工作方式整理的通用提示词，供不同模型和 Agent 按场景复制或改写。它们不是 OpenAI、Codex 或其他模型的官方系统提示词，也不要求模型伪装成特定产品或拥有特定工具。

提示词的初始灵感来自 [CL4R1T4S 中的 Sol 提示词](https://github.com/elder-plinius/CL4R1T4S/blob/main/OPENAI/Codex_Desktop/GPT-6-Sol_Prompts.txt) 和 [Astra 提示词](https://github.com/elder-plinius/CL4R1T4S/blob/main/OPENAI/Codex_Desktop/GPT-6-Astra_Prompts.md)。这些链接是第三方仓库中的文本；其标题和内容不足以证明提示词确为 OpenAI 官方系统提示词，也不能据此断言其中的模型代号、版本关系或内部安全机制属实。上游页面当前显示 Sol 文件约 1902 行、Astra 文件约 5051 行，文件会随上游变化。

## 对我有用的做法

- 让 Agent 对可在仓库或环境中查明的事实先调查，再向我询问真正涉及业务意图或取舍的问题。
- 用户提出实际工作请求时，在已授权范围内推进到可检查的结果，并报告改动和验证依据。
- 先给结论和关键证据，减少套话；技术文档按读者理解顺序组织，列表只用于并列或步骤内容。
- 代码、文档和研究任务分别使用不同的专用规则，避免一份很长的全能提示词互相冲突。

## 本地改编原则

这些提示词是可编辑的个人偏好，不是语言规范或安全策略的替代品。模型应优先遵守当前项目的约定、用户明确要求和实际工具能力。技术选择要结合代码库、目标平台、依赖版本和约束；规则不适用时应说明原因，而不是机械套用。

提示词只表达行为要求，不能赋予模型不存在的工具、权限、实时知识或可靠性。跨模型使用时，可按平台限制删改格式和工具描述；研究和版本敏感问题仍需查证一手资料。短提示词有助于控制上下文长度，但不能保证更快推理或更高准确率，效果需要在目标模型和任务上实际观察。

每次选用一个主提示词，再按任务补充项目事实和具体目标。需要代码库内可自动发现、带参考资料或脚本的专业技能时，使用相应 `SKILL.md`；本目录提示词本身不会被各 Agent 自动加载。
